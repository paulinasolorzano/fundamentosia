SECCIÓN 01 / 06

1. Primero, la idea sin palabras difíciles

Imagina que tienes varias propuestas para resolver un problema. Revisas cuáles funcionan mejor, combinas partes de algunas y pruebas pequeños cambios. Después vuelves a revisar los resultados.

Un algoritmo genético repite esta idea: proponer → evaluar → elegir → combinar → cambiar → evaluar otra vez.

Se inspira en la evolución biológica, pero aquí trabajamos con propuestas de solución. No aprende por sí solo qué es “bueno”: nosotros escribimos las reglas para evaluarlas.

Al terminar podrás: interpretar una propuesta, calcular su puntuación, explicar cómo se combina con otra y detectar si un cambio ayuda o perjudica.

Recorrido sugerido: proyectos (25 minutos), horarios (25 minutos) y actividad individual (15 minutos). No necesitas programar para completar la práctica.

2. Ejemplo 1: elegir proyectos con un presupuesto

La escuela puede gastar hasta 10 unidades de presupuesto. Quiere elegir proyectos que, juntos, aporten el mayor beneficio posible. El beneficio son puntos de utilidad definidos para este ejercicio; no es dinero ganado.

ProyectoCostoBeneficio
A · Huerto47
B · Radio35
C · Robótica59
D · Mural24

Paso 1. Escribir una propuesta

Siempre usamos el orden A, B, C, D. Escribimos 1 para incluir un proyecto y 0 para dejarlo fuera.

CódigoA · HuertoB · RadioC · RobóticaD · Mural
1010SíNoSíNo

Por eso, 1010 significa elegir Huerto y Robótica. No se lee como “mil diez”; son cuatro decisiones separadas.

Paso 2. Revisar cuánto cuesta y cuánto aporta

Costo: 4 + 5 = 9. Beneficio: 7 + 9 = 16. Como 9 no supera el presupuesto de 10, esta propuesta recibe 16 puntos.

Regla del ejercicio: si alcanza el presupuesto, la puntuación es el beneficio. Si se pasa, recibe 0 puntos. Una propuesta que no cumple no puede ganar, aunque prometa mucho beneficio.

Prueba tú: elige los proyectos

Activa o desactiva cada proyecto. Observa cómo cambia la puntuación.

Paso 3. Empezar con varias propuestas

El conjunto de propuestas se llama población. Para aprender usaremos estas cuatro, ya preparadas:

PropuestaProyectos incluidosCostoBeneficioPuntuación
1010A + C91616
0101B + D599
1100A + B71212
1000A477

Paso 4. Elegir dos propuestas para combinar

Comparamos por parejas: entre 1010 (16 puntos) y 1100 (12), elegimos 1010. Entre 0101 (9 puntos) y 1000 (7), elegimos 0101.

Esta selección se llama torneo. Elegimos al mejor de cada pareja, no necesariamente a los dos mejores de toda la población. En un programa, normalmente se sortean los participantes.

Paso 5. Combinar partes de las elegidas: cruce

Separamos las dos primeras decisiones de las dos últimas. La barra solo marca el corte:

Propuesta 1: 10 | 10
Propuesta 2: 01 | 01

Nueva propuesta 1: 10 + 01 → 1001
Nueva propuesta 2: 01 + 10 → 0110

No sumamos números: pegamos el inicio de una propuesta con el final de la otra. Las posiciones siguen siendo A, B, C y D.

Nueva propuestaInterpretaciónCostoPuntuación
1001A + D4 + 2 = 67 + 4 = 11
0110B + C3 + 5 = 85 + 9 = 14

Observa que ambos resultados son peores que 1010, que tenía 16 puntos. Combinar no garantiza mejorar.

Paso 6. Probar un cambio pequeño: mutación

En 0110 cambiamos únicamente la última decisión de 0 a 1: 0110 → 0111. Eso significa agregar el Mural.

Ahora elegimos B + C + D. Costo: 3 + 5 + 2 = 10. Beneficio: 5 + 9 + 4 = 18. Cumple el presupuesto y mejora los 16 puntos de la mejor propuesta inicial.

Elegimos ese cambio para mostrar el procedimiento. En un algoritmo genético, la mutación suele depender del azar y también puede empeorar una propuesta.

Paso 7. Formar el siguiente grupo de propuestas

Conservamos las dos mejores originales y agregamos los dos descendientes, después del cambio:

PropuestaDe dónde salióPuntuación
1010Conservada16
1100Conservada12
1001Cruce11
0111Cruce y mutación18

Este nuevo grupo es la siguiente generación. Conservar algunas buenas propuestas se llama elitismo. Podríamos repetir los pasos desde la selección usando este grupo.

Antes de seguir: explica con tus palabras por qué 1111 tiene 0 puntos y por qué 0111 tiene 18.

SECCIÓN 04 / 06

4. Ejemplo 2: organizar la carga de horarios de una escuela

Vamos a construir un fragmento del horario: cuatro clases de una hora, dos grupos y dos docentes. No es todavía la carga semanal completa de una escuela.

ClaseGrupoMateriaDocente
A1MatemáticasAna
B1HistoriaLuis
C2MatemáticasAna
D2HistoriaLuis

Cada grupo tiene su propio salón. Ambos docentes están disponibles en los dos bloques. Debemos dar las cuatro clases una vez:

  • Bloque 1: lunes de 8:00 a 9:00.
  • Bloque 2: lunes de 9:00 a 10:00.

Paso 1. Decidir qué representa el código

Las posiciones siguen el orden A, B, C, D. Ahora cada número indica el bloque asignado a esa clase. Aquí 1 y 2 son bloques; ya no significan incluir o descartar.

Código:       [1, 2, 1, 2]
Clase:         A  B  C  D
Interpretación: A y C van a las 8:00; B y D van a las 9:00.

Paso 2. Definir cuándo existe un choque

  • Un docente no puede dar dos clases en el mismo bloque.
  • Un grupo no puede recibir dos clases en el mismo bloque.

Revisamos cuatro pares. Cada par sin choque suma 1 punto:

Par que revisamosRegla para sumar 1 punto
A y B · Grupo 1Deben tener bloques distintos
C y D · Grupo 2Deben tener bloques distintos
A y C · Docente AnaDeben tener bloques distintos
B y D · Docente LuisDeben tener bloques distintos

Puntuación = cantidad de pares sin choque. Va de 0 a 4. Solo 4 puntos significa que el horario cumple todas las reglas de este ejemplo. Los puntajes menores sirven para comparar propuestas, pero todavía no son horarios válidos.

Paso 3. Evaluar las propuestas iniciales

PropuestaA ≠ BC ≠ DA ≠ CB ≠ DPuntos
[1,2,1,2]SíSíNoNo2
[2,1,2,1]SíSíNoNo2
[1,1,1,1]NoNoNoNo0
[2,2,2,2]NoNoNoNo0

En [1,2,1,2] los grupos no chocan, pero Ana tiene A y C al mismo tiempo, y Luis tiene B y D al mismo tiempo. Por eso obtiene 2 puntos y aún no sirve.

Paso 4. Seleccionar

Comparamos la primera propuesta con la tercera: gana [1,2,1,2], con 2 puntos. Comparamos la segunda con la cuarta: gana [2,1,2,1], también con 2 puntos.

Paso 5. Cruzar después de las dos primeras clases

Propuesta 1: [1,2 | 1,2]
Propuesta 2: [2,1 | 2,1]

Descendiente 1: [1,2 | 2,1] → [1,2,2,1]
Descendiente 2: [2,1 | 1,2] → [2,1,1,2]

Tomamos las asignaciones de A y B de un padre y las de C y D del otro. Cada clase conserva su lugar en el código: no se elimina ni duplica ninguna clase.

Paso 6. Evaluar de nuevo

Ambos descendientes obtienen 4 puntos. Mira el horario del primero, [1,2,2,1]:

HorarioGrupo 1Grupo 2
Lunes 8:00–9:00A · Matemáticas · AnaD · Historia · Luis
Lunes 9:00–10:00B · Historia · LuisC · Matemáticas · Ana

Cada grupo recibe una sola clase por bloque y cada docente imparte una sola clase por bloque. Las cuatro clases quedan asignadas.

Paso 7. ¿Qué pasa si probamos una mutación?

En [1,2,2,1] cambiamos el bloque de D, de 1 a 2: obtenemos [1,2,2,2].

Ahora C y D chocan en el grupo 2; además B y D chocan para Luis. Solo cumple A ≠ B y A ≠ C, así que baja de 4 a 2 puntos. En este caso la mutación perjudicó el resultado.

Para formar una nueva población de cuatro, podemos conservar [1,2,1,2] y [2,1,2,1], y agregar [1,2,2,1] y el descendiente mutado [2,1,1,1]. Sus puntajes son 2, 2, 4 y 2. Conservamos así una propuesta válida, aunque otro cambio haya empeorado la segunda.

Prueba tú: mueve las cuatro clases

Elige el bloque de cada clase. La tabla y la explicación se actualizan.

En una escuela real también habría que registrar días, salones, disponibilidad de docentes, horas semanales por materia y límites de carga. Las reglas obligatorias deben cumplirse antes de considerar preferencias, como reducir horas libres. Este ejemplo solo enseña el mecanismo.

"""MODELO: Huerto, Radio, Robótica y Mural. Python 3, sin paquetes externos."""
# Posiciones: A = Huerto, B = Radio, C = Robótica, D = Mural.
COSTOS = [4, 3, 5, 2]
BENEFICIOS = [7, 5, 9, 4]
PRESUPUESTO = 10


def evaluar(codigo):
    # Cada 1 indica que debemos sumar el proyecto de esa posición.
    costo = 0
    beneficio = 0
    for i in range(4):
        if codigo[i] == "1":
            costo += COSTOS[i]
            beneficio += BENEFICIOS[i]
    puntuacion = beneficio if costo <= PRESUPUESTO else 0
    return costo, beneficio, puntuacion


def torneo(a, b):
    # evaluar devuelve tres valores. El índice 2 es la puntuación.
    if evaluar(b)[2] > evaluar(a)[2]:
        return b
    return a  # En empate conservamos el primero.


def cruzar(a, b):
    # [:2] toma las dos primeras cifras; [2:] toma las dos últimas.
    hijo1 = a[:2] + b[2:]
    hijo2 = b[:2] + a[2:]
    return hijo1, hijo2


def mutar_ultima(codigo):
    # [:3] conserva las tres primeras cifras. Solo cambia la última.
    nueva = "0" if codigo[3] == "1" else "1"
    return codigo[:3] + nueva


if __name__ == "__main__":
    poblacion = ["1010", "0101", "1100", "1000"]
    print("Inicial: código, (costo, beneficio, puntuación)")
    for codigo in poblacion:
        print(codigo, evaluar(codigo))

    padre1 = torneo(poblacion[0], poblacion[2])
    padre2 = torneo(poblacion[1], poblacion[3])
    print("Padres:", padre1, padre2)

    hijo1, hijo2 = cruzar(padre1, padre2)
    print("Hijos:", hijo1, evaluar(hijo1), hijo2, evaluar(hijo2))

    # En el primer ejemplo se modifica el SEGUNDO hijo.
    mutado = mutar_ultima(hijo2)
    print("Segundo hijo mutado:", mutado, evaluar(mutado))

    # Ordenar por puntuación y conservar los dos mejores originales.
    elites = sorted(poblacion, key=lambda c: evaluar(c)[2], reverse=True)[:2]
    nueva = elites + [hijo1, mutado]
    print("Nueva población:", nueva)
    print("Mejor puntuación:", max(evaluar(c)[2] for c in nueva))
    # Recorrido fijo para aprender: no es una búsqueda aleatoria completa.

Qué deberías observar: los padres son 1010 y 0101; el cruce produce 1001 y 0110; la mutación del segundo hijo produce 0111. La nueva población es 1010, 1100, 1001 y 0111; su mejor puntuación es 18.
