1. Primero entiende el dibujo

Queremos ir de A, la entrada, a G, la biblioteca. Hay dos caminos principales: uno pasa por C y otro pasa por B, D, E, F y H.

Los círculos son nodos

Cada letra identifica un lugar. A y C son dos nodos distintos. En este ejemplo no necesitas saber las coordenadas de esos lugares.

Las líneas son conexiones

Una línea entre A y C indica que puedes ir de uno al otro. El nombre formal de esa línea es arista.

Todo el dibujo es un grafo

Un grafo reúne nodos y conexiones. Como las líneas no tienen flechas, puedes moverte en ambos sentidos.

Un camino une el inicio y la meta

A → C → G es un camino. Tiene tres nodos y dos conexiones. La posición inicial no cuenta como movimiento.

Cada conexión vale 1. Una línea larga y una corta valen lo mismo: este dibujo muestra qué lugares están conectados, no las distancias reales.

¿Por qué le llamamos grafo y no árbol de decisión?

Este grafo tiene caminos que se vuelven a unir y puede tener ciclos: A → B → D → E → F → H → G → C → A permite volver al punto de partida.

Un árbol no tiene ciclos. Un árbol de búsqueda muestra cómo se abren las alternativas desde el inicio. Un árbol de decisión es otro modelo, por ejemplo para clasificar mediante preguntas. Aquí usaremos la palabra grafo.

Antes de seguir: señala un nodo, una conexión y la meta. Cuenta las conexiones de A → B → D → E → F → H → G.

2. BFS, explicado paso a paso

Imagina que estás en A. Puedes ir a B o a C. BFS revisa ambas posibilidades antes de explorar lugares más lejanos.

Para recordar qué sigue, hace una fila de espera. En programación se llama cola. El que llegó primero se revisa primero.

  1. Al comenzar: solo espera A.
  2. Revisa A: descubre B y C. La fila queda B, C.
  3. Revisa B: descubre D. Como C ya esperaba, la fila queda C, D.
  4. Revisa C: descubre G. La fila queda D, G.
  5. Revisa D: estaba antes en la fila. Guarda E detrás de G. Después llega el turno de G.
  6. Encuentra G: recupera el camino A → C → G.

La fila sirve para ordenar la búsqueda. No es el camino que recorrerá el personaje.

¿Cuándo te conviene?

Cuando quieres llegar con el menor número de movimientos y todos los movimientos cuestan lo mismo. Aquí encuentra A → C → G: dos conexiones.

Si cruzar un pasillo tarda un minuto y otro diez, contar pasillos ya no basta para encontrar el viaje más rápido.

3. El mismo camino de dos maneras

Haz clic en Un paso. Cada clic revisa un nodo, que también puedes ver como una casilla. La letra con borde naranja es el nodo que se acaba de revisar.

Cambia de vista sin perder el paso. Cada casilla libre corresponde al nodo con la misma letra. Una conexión equivale a un movimiento horizontal o vertical.

Amarillo: descubierto, esperando turno.
Verde claro: ya revisado.
Verde oscuro: camino final.
Punteado en el grafo o barrera oscura entre casillas: conexión cerrada.

Esta lista puede ser diferente del camino final. El programa prueba posibilidades en su memoria; el personaje recorrería después el camino encontrado.

¿Cómo recuerda el programa el camino?

Para cada nodo nuevo guarda desde dónde llegó. Por ejemplo: llegó a C desde A y llegó a G desde C. Al terminar, sigue esas notas hacia atrás y obtiene A → C → G.

¿Cómo guarda las conexiones?

Con una lista de vecinos. "A": ["B", "C"] significa que desde A se puede ir directamente a B y a C.

Para que el ejemplo se repita igual, usamos las letras en orden alfabético. En DFS las apilamos al revés para que la letra menor quede arriba. En A* comparamos primero la suma; si empatan, lo recorrido y después la letra.


4. ¿En qué situaciones sirve?
Los nodos no siempre son lugares. También pueden ser personas o situaciones de un juego. Estos son ejemplos de aplicación del algoritmo o de sus variantes.
¿A cuántas conexiones estás de tu artista favorito?
La situación: Quieres saber si hay una cadena de conocidos que te conecte con una cantante.
Cómo lo representamos: Cada persona es un nodo. Una conexión indica que dos personas se conocen. BFS busca una cadena con el menor número de conexiones.
Para qué sirve: Sirve para explorar redes de contactos. No mide amistad, confianza ni la posibilidad de que alguien te presente.
Un juego: llegar a la salida con pocos movimientos
La situación: Un personaje puede moverse entre habitaciones y cada puerta cuenta como una acción.
Cómo lo representamos: Cada habitación es un nodo. Cada puerta es una conexión. BFS encuentra una salida usando el menor número de puertas.
Para qué sirve: Útil para diseñar pistas o comprobar soluciones de un juego con movimientos de igual costo.


5. ¿Qué tiene que ver con la IA?
Un programa necesita elegir acciones para llegar a una meta. En vez de adivinar, representa las opciones y las explora con una regla.
BFS pertenece a la búsqueda y resolución de problemas dentro de la IA clásica.
Su categoría es búsqueda no informada: no usa una pista sobre lo que falta.
Esto puede ayudar a planear acciones en juegos o robots. El algoritmo no aprende de ejemplos: ejecuta reglas de búsqueda. También se utiliza en informática fuera de la IA.

# BFS · Buscar de A a G en un grafo no dirigido.
# Cada conexión cuesta 1. Los vecinos se consideran alfabéticamente.
from collections import deque


def reconstruir(anterior, nodo):
    ruta = []
    while nodo is not None:
        ruta.append(nodo)
        nodo = anterior[nodo]
    return ruta[::-1]


def buscar(grafo, inicio, meta):
    pendientes = deque([inicio])
    descubiertos = {inicio}
    anterior = {inicio: None}
    while pendientes:
        actual = pendientes.popleft()
        if actual == meta:
            return reconstruir(anterior, actual)
        # Vecinos en orden alfabético.
        for vecino in sorted(grafo[actual]):
            if vecino not in descubiertos:
                descubiertos.add(vecino)
                anterior[vecino] = actual
                pendientes.append(vecino)
    return None

Las palabras del código, sin complicaciones
  • grafo: guarda quién está conectado con quién.
  • pendientes: guarda los nodos que esperan ser revisados.
  • anterior: recuerda desde dónde llegamos a cada nodo.
  • buscar: es la función que intenta encontrar un camino.
  • reconstruir: recupera el camino usando las notas guardadas.
  • None: indica que no se encontró un camino.
descubiertos evita guardar repetidamente el mismo nodo.  append agrega al final de la fila y popleft saca el primero.
